### Two things you asked for are not in this plan

- **No task-level Gantt.** With two volunteers around full-time jobs, it goes stale within a month. You would keep trusting dates nothing re-baselined. I use a dependency-gated milestone plan instead. It has about 65 milestones, each with one owner and a binary finished state.
- **No weekly re-baseline.** A weekly per-track pass that nobody is on duty to run turns into an invite you decline. I use 10 pre-written checkpoints, 2 to 4 weeks apart. Each one checks every milestone due since the previous checkpoint, so the quiet middle (Dec–Feb) stays watched.
- **Exception:** if you two already have a standing weekly call, spend 10 minutes of it on the "gates at risk" list. Don't start a new meeting for this.

### Replan procedure

1. List each track's done, late and not-started milestones against this plan.
2. Flag every gate now at risk.
3. Spend slack in order: latest-safe slack, then scope tier, then scope cuts.
4. Cut the item whose removal unblocks the most downstream milestones, not the one that is merely most behind.
5. Rewrite the remaining checkpoint conditions against the new plan.
6. Tell each other which lever was spent.

The date never moves. Scope moves.

### Pass/fail check on the plan itself

- Every checkpoint has a date, a condition, an action and an owner.
- Every track has exactly one owner.
