# ThreadFest positioning brief (draft for your validation)

## Recommendation up front

**Don't launch ThreadFest as a new category. Launch it as a subcategory, and keep "docs-ops" as the topic term you try to grow into a category later.**

Your plan fails the skill's own promotion condition for a new category. It requires multi-edition runway, existing sponsor relationships, and a distinctive brand to pay the education tax. You have a first edition, part-time organizers, and zero sponsors. The skill lists "new category on first-edition resources" as a named failure mode. A first edition already carries "unproven", and a new category adds "I don't know how to judge this."

**"If we define the category, nobody can catch us" doesn't hold up.** A category name is a few words anyone can reuse. A bigger event could add a "docs-ops track" next year and take the term. Defining the category doesn't protect you. The things that do are curation, community trust, and a legible lineup. Those are what you should spend your effort on.

⚠️ **Check the name before you commit.** "DocOps" already circulates as a term for documentation operations. If so, "docs-ops summit" isn't a new category. It is an existing niche label, and "genuinely nothing out there" needs checking. Search for it before you write any copy.

## 2. Competitive alternatives (hypotheses, not research)

Run the do-nothing diagnostic. For a niche like this, the likely cause is **no acute trigger**. The positioning answer to that gap is value themes tied to a real deadline in the attendee's work, such as onboarding, incidents, and migrations.

## 3. Unique attributes chained to value themes

Only one attribute is confirmed so far: **the topic intersection** (DX × internal docs). It passes the "only this event" test only if your search confirms it.

- So what: attendees skip the public-docs and tooling talks that dominate adjacent events.

You have no curator or format attribute yet. That is the gap to close in sections 6 and 7.

## 4. Best-fit segments

- **Attendee:** the narrowest group that feels the pain. I'd test **platform/DX engineers and technical writers who own internal documentation at companies large enough that docs rot**. Don't write "anyone who cares about docs or DX." The skill deletes that framing.
- **Sponsor (later):** vendors in internal developer portals, docs tooling, and developer search. They must have an existing budget line. A new category has none, which is another reason the subcategory frame helps you.

## 5. Category strategy: three candidates

| | A. Subcategory (recommended) | B. Head-to-head | C. New category (your plan) |
| --- | --- | --- | --- |
| Frame | "Practitioner-first conference on internal docs as developer experience" | "The best DX conference" | "The docs-ops summit" |
| Effort | Medium | Zero education cost | Highest |
| Value if it works | High | Lowest, judged on the incumbent's terms | Highest |
| Fit for you now | Fits a 150-person first edition | You can't out-execute DX incumbents | Fails the runway, sponsor and brand condition |

The skill's ranking is effort `new > head-to-head > subcategory`, value `new > subcategory > head-to-head`, and efficiency `subcategory > head-to-head > new`. You have no runway, so efficiency decides it. Candidate A is the pick.

**Path to C:** use "docs-ops" as the vocabulary inside the event, in talk titles, the CFP and the hallway track. If edition two or three shows attendees and sponsors using the term unprompted, promote it to a category then.
