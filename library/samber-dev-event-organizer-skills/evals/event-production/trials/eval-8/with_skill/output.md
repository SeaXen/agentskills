# After-event plan for the recorded talks (one room, recorded, not streamed)

Assumptions, since you asked for the plan rather than an interview. Tell me if any is wrong, because each one changes a section below.
- **Capture posture:** recorded for later, not streamed. A recorded-for-later setup forgives short failures, so the plan puts its effort into the pipeline and the paperwork.
- **Recurring event, same setup.** That justifies spending effort on things that outlive this edition: a written pipeline, a named owner, and a consent record.
- **Consent record:** none exists today. Last year's failure was a consent gap, not a file gap.

## Why last year failed

There were three failures:
1. **No consent record.** Nobody could say who had agreed to be recorded. That is why 8 of 19 talks were dropped, and it is the main cause.
2. **No owner and no date.** The files sat on one laptop until March. Nobody was responsible for them after the crew left.
3. **No check that the files played.** You can't tell which talks were usable or what they needed.

The fix is to move the decisions before the event and put an owner and a date on every step after it.

## 1. Consent record (start now, finish before the event)

Ask every speaker at acceptance, not at the venue. Keep one table with one row per talk, in one shared place that more than one person can open.

| Field | Values |
|---|---|
| Talk ID and speaker | |
| Recording OK | yes / no / not yet asked |
| Publishing OK, and where | yes / no, with channels (for example your own channel, or also third-party platforms) |
| Slides included | yes / no |
| Audience Q&A included | yes / no |
| Date and how the answer was given | written, with the date |
| Opt-out after the talk | open until the stated date |

Rules:
- **Unknown means unpublishable.** A row that is not an explicit yes is marked unpublishable. A camera in the room is not consent.
- **The record must be complete before doors open.** This is the pre-event gate. Chase every "not yet asked" at T-4 weeks.
- **Make saying no easy.** A speaker may refuse recording entirely, or allow recording but not publishing. Tell the crew which talks are no-record so they can stop the camera in the room. Opting out after the fact is handled in the edit.
- **Warn speakers about background music in demos.** Platforms can take a video down for incidental music.
- **Audience on camera:** put a visible notice at the door and seat the audience so they stay out of frame.
- **Ask for a short post-talk window.** For example, a speaker can withdraw within 7 days of seeing the video. This is a number you set, not a standard.

Last year's dropped talks: if the 8 files still exist, email those speakers now. This also tests the process cheaply, and you may recover some of them.

## 2. Capture on the day

This is the minimum that keeps the files usable (recorded, not streamed):
- **Fixed camera taking audio from the mixing board.** Don't use the camera's own microphone, because room audio from the back makes a file nobody finishes watching.
- **A spare mic live within reach, plus spare batteries and cables.**
- **A second audio recorder outside the live mix.** Promote this from optional to required if any talk can't be repeated.
- **A monitor at the production desk showing the recorded output.** This catches silent failures, such as a recording that has been black for 40 minutes.
- **File names** like `roomA-YYYYMMDD-HHMM-talkID`, with clocks set to one time source that morning.
- **One 60-second test recording, played back, before the first talk.** Check playback, not a level meter.
- **Copy files off between talks, not in one pass at the end.**

Name one production owner who is not also speaking, MCing or running registration. A house technician alone doesn't count, because nobody in that arrangement owns your files.

## 3. Pipeline after the event

Every step has an owner and a date. The day offsets below are my proposals, so adjust them to your team.

| When | Step | Owner |
|---|---|---|
| Event day, before the crew leaves | Verify all 19–20 files exist and play (open each one, skim the start, middle and end). Copy to two places (the production laptop plus a shared drive or cloud). Log any failed talk. | Production owner |
| Event day | Hand the verified files to the post owner. The laptop is no longer the only copy. | Production owner → post owner |
| E+3 days | Check every talk against the consent record. Mark each one publish / do not publish. | Post owner |
| E+3 to E+21 days | Edit (trim and normalize audio). Do the Q&A and slides cuts per the consent row. | Editor |
| E+21 days | Send each speaker their own preview link, which opens the withdrawal window. | Post owner |
| E+28 days | Publish all talks that are clear. Send each speaker their link. | Post owner |
| E+35 days | Retrospective: count published vs scheduled, and note where it stalled. | Organizer |

Name the post owner and the editor before the event, not after. A pipeline with no owner after the event is exactly what happened last year. Put the publication date in the calendar now.

## 4. What to track, and what each number triggers

These are targets you set yourself, not benchmarks.
- **Capture completeness:** talks with a usable recording ÷ talks scheduled. Last year was 11 of 19 published. If this is below your target, add a redundancy rung next edition.
- **Time from event end to published video.** If it slips past E+28 days, find the step that stalled and give it an owner or paid help.
- **Consent coverage:** rows with an explicit yes or no ÷ talks, measured at T-1 week. It must be 100% before the event.

## 5. Timeline from now (event in about five months)

- **Now:** name the production owner, post owner and editor. Create the consent table. Contact last year's dropped speakers.
- **At each speaker acceptance:** collect consent.
- **T-4 weeks:** chase every open consent row. Send the venue its questions in writing through venue sourcing.
- **T-1 week:** consent coverage 100% or escalate.
- **Event day:** run the capture checklist, the test recording and the verified copy.
- **After the event:** run the pipeline table.

## Open questions

These change the plan, so answer them when you can:
1. Do you contract a supplier or use volunteers? That changes who owns the brief.
2. Is the venue's house technician included, and what are they responsible for?
3. Who will be post owner and editor?
4. Do you want to publish on third-party platforms, or only your own channel? That changes the consent wording.
5. Is the room small enough that one fixed camera reads the slides? If not, move up one rung to a camera with an operator.
