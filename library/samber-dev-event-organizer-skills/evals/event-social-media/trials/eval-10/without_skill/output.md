Four problems, four fixes. Total setup is about 3 hours. After that, the weekly cost is about 30 minutes.

## 1. Shared password and anyone-posts-anytime

1. Pick one scheduling tool with per-user logins, roles, and an approval step. Buffer, Hootsuite, and Sprout all have these.
2. Add all 5 organisers as named users. Make 2 of you publishers. Make the other 3 drafters whose posts need approval.
3. Connect the LinkedIn page through the tool's own login flow, so nobody holds the page credentials.
4. For Mastodon, use a scheduler that supports it, or schedule natively in the Mastodon web UI. Two organisers hold that login. Turn on 2FA.
5. Rotate the current password now. Put the remaining shared secrets, such as recovery email and 2FA backup codes, in a password manager vault with 2 holders.
6. Write a short written policy and pin it to the organiser chat:
   - Draft goes in the tool.
   - A second organiser approves before it publishes.
   - Nobody posts from the native app.

## 2. Requests landing in five inboxes

Last edition's lost sponsor request came from this. Fix it with one shared inbox and one owner per week.

1. Create one shared address, such as `team@gonorth…`. Give it a shared inbox tool or a plain group alias. Use a help-desk tool if you want assignment, or a shared Google group if you want free.
2. Put that address everywhere: the sponsor form, speaker emails, the website, and your social bios.
3. Add a rota with one "on-call" organiser per week. In the final 2 weeks before doors, switch to one person per day.
4. Set a rule: no organiser handles a request from a personal inbox. Forward it to the shared address within 24 hours.
5. Set a response target. Acknowledge within 1 business day. Add a short "urgent, day-before" path: a phone number or chat handle that only the on-call person holds.
6. Keep one tracker, a table or board, with these columns: sender, request, owner, deadline, status. The on-call person reviews it daily in the last 2 weeks.

The night-before request would have hit the on-call person's phone. It would also have appeared as an open item in the tracker.

## 3. Identical text on LinkedIn and Mastodon

The audiences differ in what they want, so write two versions of each post. Do not translate one into the other.

- **LinkedIn, for the budget signers:** lead with outcomes. Use the talks as proof of what their team will learn, plus cost, dates, group-ticket pricing, and a short "why send your team" line. Use a clear call to action to register.
- **Mastodon, for practitioners:** lead with the talk itself. Give the title, the speaker, the technical hook, and a link to the schedule. Skip sales language. Use hashtags such as `#golang`, with CamelCase for multi-word tags. Write alt text on every image. Mastodon users notice and reward that.
- Plan one content calendar with a column per platform. Each topic gets two drafts, and the scheduler publishes each to its own channel.
- Share the load. Give one organiser LinkedIn and one Mastodon, plus a backup for each.
- Start measuring. For LinkedIn, track registrations and group-ticket enquiries. For Mastodon, track schedule-page clicks and talk-level engagement. Use a different link tag per platform so you can tell them apart.

## 4. Sponsor form already asks for a handle

Use it. It costs nothing.

1. Check which handle the field asks for. Split it into two optional fields: LinkedIn company page and Mastodon or other handle.
2. Add a field for the sponsor's single point of contact and a backup contact. This feeds the shared inbox.
3. Add a field for urgent day-of contact: a mobile number.
4. Copy the answers into the tracker from section 2.
5. Tag sponsors in LinkedIn posts. Do it on announcement day and again at the event. Sponsors share what mentions them, which extends your reach to their budget-holders.
6. Add a line to the form: "We will tag you from our event accounts. Tell us if you prefer not to be tagged."
