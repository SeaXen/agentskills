# Guest brief: Brassard 4th edition

✅ **Result: nobody is left in scope. Set up no VIP track for any of the three.**

Each person already has an owner, or needs nothing. Neither of those cases makes them a VIP-management guest. A guest qualifies only if their presence creates an obligation the door and help desk can't absorb: external protocol, security, discretion, or a dependency exposure. Title and fame don't count.

I didn't ask the interview questions. I assumed Brassard is community-run: volunteers, tickets at cost, sponsors recovering costs. The result would hold at the vendor pole too, because the routing doesn't depend on pole.

## 2. What to set up

- **Identification breadth:** no list. There is nobody to put on one, and the roster has no valid row. Every row needs an obligation type, and none of the three has one.
- **Program posture:** no posture. A formal program or runbook would manufacture a tier for nothing.
- **Visibility:** same badge, same door, same seating as everyone. No marker, no stage mention, no reserved row. Don't use the word "VIP", including on the radio.
- **Escort:** none. No greeter, no contact card.

## 5. Handoffs and day-of decisions

- **Seating and schedule:** nothing to hand to `event-schedule-design` or `event-run-of-show`.
- **Access needs:** any access need from any of the three goes to `event-accessibility-inclusion`.
- **Photos:** the standard event photo policy applies to everyone. Nobody needs a named decider for a case that doesn't exist.

## 6. Measurement and memory

- **Tier visibility:** after the event, ask two attendees near each of the three whether anyone was treated differently. At a flat-register event, any "yes" is a finding.
