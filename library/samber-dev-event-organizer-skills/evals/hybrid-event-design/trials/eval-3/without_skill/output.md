# Sanity check: hybrid Q&A plan for Kestrel Summit

**Verdict:** Discord is a fine channel. The staffing is the flaw. Nobody owns the remote questions, so they will go unanswered, and remote attendees will notice quickly.

## What breaks

1. **"Half an eye" means no owner.** AV volunteers are busy exactly when questions arrive: during talks, mic swaps, and stream glitches. Nobody checks the channel at the moments it matters.
2. **Two rooms, one channel.** Volunteers can't tell which questions are for which room or session, so they either duplicate effort or each assume the other has it.
3. **Seeing a question is only half the job.** Someone still has to read it aloud to the speaker. AV volunteers aren't on stage, so you need the session chair or moderator to do it. The plan doesn't say who.
4. **Stream delay.** A typical 10–30 second lag means remote questions arrive after the speaker has moved on. Q&A needs to sit at the end of the talk with a buffer, not be taken live mid-talk.
5. **Remote viewers can't hear the room.** If in-room questions aren't repeated into the stream mic, remote attendees are lost. Either use a mic runner or have the chair repeat every question.
6. **Mixed traffic.** "No audio" and "stream froze" messages will land in the same channel as questions, and AV volunteers will triage those first. The questions will lose.
7. **No upvoting.** In a Discord channel the loudest or earliest question wins, not the best one.
8. **No fallback.** If Discord or the stream link fails, nothing replaces it.

## Fix (still near-zero cash cost)

1. **One remote host per room.** Recruit them from your community and make it their only job. They can be remote themselves, because they only need the stream and Discord. This is the key change, and it costs people-time, not money.
2. **Split channels:** `#room-a-questions`, `#room-b-questions`, and a separate `#remote-help` for tech problems. Have a different person watch `#remote-help` than the question hosts.
3. **Make it easy to ask.** Pin the channel link in the stream description and on the first slide of every session. Tell remote attendees to prefix questions with the session name or number.
4. **Add upvoting if you can.** Use the 👍 reaction in Discord, or a free tier of Slido or similar. Decide before the event which one you're using. Don't run two.
5. **Define the handoff.** The remote host flags the top 2–3 questions to the session chair, and the chair reads them aloud and names the asker. Brief the chairs before the event.
6. **Rehearse.** Do one 30-minute dry run with stream, Discord, host, and chair. Check delay, audio, and the full question path.
7. **Set a fallback.** If Discord fails, use a backup channel such as the stream platform's chat. Write the switch-over step on one card.
8. **Moderate the channels.** Set slowmode, restrict posting to verified members, and name a moderator for spam.

## Questions for you

- How many remote attendees do you expect? About 10 changes the answer from 200.
- Is the stream live-only, or also recorded? It affects whether the chair can defer questions to async.
- Do you have a session chair or moderator per room already?

## Bottom line

Keep the Discord approach, but add one dedicated remote host per room and one named handoff to the chair. Without those two, the plan is a stream with a chat box nobody reads.
