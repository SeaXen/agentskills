# Is the disruption order good enough to run Nimbus Conf on?

**No, not as written.** It is a sound order for one audience, and you have two. It needs a written addendum before the day. The format decision is closed, so I am not reopening hybrid.

## Why the order fails for a hybrid day

The order reads: protect the plenary or keynote, protect the headline commitment, minimize how many other sessions the fix disturbs, then lock the revised grid. Each step says "the audience" in the singular. It never says what happens when a remote-side failure and an in-room problem compete.

Two of its clauses also break on a hybrid grid:

- **"Minimize how many other sessions the fix disturbs"** counts only room sessions. It doesn't say whether a session moved to fix an in-room problem takes its remote programme with it.
- **"Lock the revised grid"** locks the room. The stream's holding cards, remote channel posts and remote eligibility column aren't covered, so the two audiences can end up on different grids.

## What to add, in writing

These are the same disruption order with a second audience bolted on. Each is marked as either documented practice or a decision that is yours to make.

**Documented defaults** (hybrid conference and AV-crew practice; sources are in `references/dual-audience-cue-track.md`):

1. **Keep the room going and fix a dead feed in parallel.** A planned pause is an exception you state in advance, not a reflex. Dagstuhl 2021 names the pause question as one organizers must decide explicitly, and VLDB 2021 kept running through its hiccups.
2. **Give up on a feed through the technical chain.** The AV technician escalates to a senior organizer, so a volunteer is never alone with that call. The room lead does not make it. Name the technician's escalation point before the day.
3. **Name a live-chat contact for the remote side.** Use a person, not an inbox checked between sessions. When something breaks, say what broke, what still works, and where to watch. FOSDEM's 2015 keynote incident is the model.

**Two decisions with no documented answer.** Nobody can tell you these, so someone on your team must decide them now and be named as the decider. Don't present either as industry practice.

4. **Who gets the technician when the remote-side person and the room lead need them at once?** I'd suggest an explicit rule. Fix the room first if the keynote is live in the room, otherwise fix the feed first. The right rule depends on your crew, so the schedule owner picks it.
5. **When a session moves to fix an in-room problem, does the remote programme move with it or drop it?** Decide per eligibility rung. If the remote audience was promised that session, it follows.

## What your hybrid setup changes

You have two streamed rooms with live Q&A. The skill calls this "a staffing problem before it is a technical one."

- **Staffing.** Nobody standing in one room can see the other room's output. The skill's default moves up to a watcher off the floor plus an advocate in each streamed room. The watcher is the one person who notices a dead feed, and the advocate is the one who relays remote questions.
- **Role clash.** The room lead can't double as the remote advocate. The room lead owns the clock, cuts Q&A and escalates. That is exactly the job that competes with relaying a remote question at the moment both come due. Name a separate person per streamed session.
- **Parity depth.** If you can't name a person for a session, drop it to feed-only. An open question channel nobody reads is worse than no channel.

## Cue-track rule for the run of show

Add one column to the run of show, not a second document. For every row it records what the stream shows, who owns it, and what the remote audience is told. A disruption changes the room column and the stream column in the same row, in the same edit. The cue sheet should also flag:

- every gap, with at least a holding card, so a remote attendee can tell a break from a failure
- every spoken announcement in the room (delay, room change, swapped speaker), each needing a stream entry

## Gate checks before the first session

- Every remote-eligible session has a named person for the remote side, or its return path is closed.
- Every cue-sheet row that changes what the room sees also says what the stream shows.
- The disruption order states in writing what happens when a remote failure and an in-room one compete, and who decided it.
