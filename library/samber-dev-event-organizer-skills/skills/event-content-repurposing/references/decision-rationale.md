# Decision rationale

Where each boundary in the opening table comes from, and the full dominance-audit reasoning behind Menus 1-3's efficiency lines.

Contents: 1. Which siblings state the boundary back - 2. Menu 1 dominance audit - 3. Menu 2 dominance audit - 4. Menu 3 dominance audit.

The three audits below check this skill's own menus against their own axis lines. They are internal consistency checks, never evidence that the rankings match measured outcomes.

## 1. Which siblings state the boundary back

A boundary only one side states is a boundary only one side will hold. Read each line below as a check on whether the sibling agrees, not as a claim it has signed up to anything.

- **`samber/dev-event-organizer-skills@event-production`** claims the publication pipeline in its own description, and its workflow runs that pipeline from verifying the files through editing, the consent check, publication, and sending each speaker their own link. It wrote the pipeline as a closed loop and never names this skill.
- **`samber/dev-event-organizer-skills@event-social-media`** states the split from its own side twice: once as an opening boundary, assigning clips, threads and articles made from talk recordings to this skill, and again in its failure modes, where it hands the archive over and stops.
- **`samber/dev-event-organizer-skills@event-speaker-experience`** owns the speaker point of contact, documented recording consent and its per-format opt-out asymmetry, and the post-event follow-up. It never names this skill.
- **`samber/dev-event-organizer-skills@event-marketing-plan`** owns the attendee-acquisition plan and its funnel targets, and never names this skill. Handing it an inventory is this skill's obligation, not a scope that skill has claimed.
- **`samber/dev-event-organizer-skills@tech-podcast-youtube-channel`** restates the boundary from its own side: it treats a one-off derivative tied to one edition's captured output as this skill's artifact, and its archive-only rung publishes what this skill already makes.
- **`samber/dev-event-organizer-skills@event-debrief`** describes its own recap-only rung as what happened, numbers, photos and thanks, with no findings, and pairs it with the team's retrospective at its default rung. It never names this skill.

## 2. Menu 1 dominance audit

4 rungs, 6 pairs, and no strict dominance relation exists. Five pairs are incomparable - each rung that wins on sustained presence loses on completion - and the sixth, drip against evergreen re-surfacing, has drip ahead on both value axes but costing more effort, which is a trade and not a dominance.

The check is therefore vacuous here, and a vacuous check is not evidence the order is right. Nothing in this menu's structure could have caught a bad ordering, so the efficiency line rests entirely on the argument in the menu itself rather than on the audit.

Two published findings back the sustained-presence axis without settling the menu's own trade:

- A randomized field trial of video-on-demand release strategies (Carnegie Mellon, Universidade Católica Portuguesa and the University of Texas, published in _Marketing Science_) found viewers given a gradual release were 48% more likely to keep using the platform than viewers given every episode at once. The effect reversed for viewers who already binge, a case this menu's own compounding-mandate question already screens for.
- SoCS 2020 rejected releasing every talk simultaneously, specifically because it would undermine the tightly knit, focused-interaction community the event exists to build, and scheduled talks into themed sessions instead.

Neither measures a conference-talk view count, and neither is presented as one. Both back the value axis's own reasoning, never the vacuous dominance check.

## 3. Menu 2 dominance audit

5 rungs, 10 pairs, exactly one strict dominance relation: the written write-up over the audio cut. The write-up is ahead on both value axes and costs less effort, so it must rank above; it does, first against last.

The other nine pairs are trades: every remaining rung that leads on one value axis either trails on the other or costs more effort. This menu is therefore clean by care, not by construction - the one relation that existed was checked and honoured.

## 4. Menu 3 dominance audit

4 rungs, 6 pairs, and no strict dominance relation exists. Five pairs rise monotonically - value climbs with effort, so neither rung is ever both better and cheaper. The sixth is the exception and is worth stating rather than folding into the rule: the ready-made asset costs less than the dated joint push and leads it on take-up, and it is blocked only because it trails on reach.

The check is vacuous, and a vacuous check is not a pass. Nothing here could have caught a wrong order. The efficiency line therefore stands on one argument and nothing else: a sentence added to a message somebody is already sending is the cheapest positive-value move available.
