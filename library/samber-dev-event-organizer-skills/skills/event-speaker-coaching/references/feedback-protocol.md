# Feedback protocol: worked notes and scripts

Load when writing or reviewing feedback on an outline, a deck or a dry run.

## Contents

## Good and bad notes

```
// ✓ Good - points at a moment, names the effect, offers one move
Change: Minute 4-9 explains the history before the problem. The room doesn't know
why it should care yet. Try opening on the outage story, history after.

// ✗ Bad - a trait, no moment, no move
You need to be more engaging at the start.

// ✓ Good - specific keep
Keep: The before/after latency chart on slide 11. The room got it in two seconds.

// ✗ Bad - empty keep, reads as padding before the "but"
Great talk overall!

// ✓ Good - question that lets the speaker find the fix
What should someone do on Monday after your last slide?

// ✗ Bad - identity-coded, unfixable
Try to sound more confident and less academic.

// ✓ Good - blocker stated plainly, reason attached
Blocking: After the cuts we agreed, the run still took 27 minutes against a
25-minute talk time. The mark is about 22, so about 5 more need to go. Which section?

// ✗ Bad - over-time "fix" that makes it worse
Just talk a bit faster in the middle section.
```

## Written review template

```
Talk: {title} - {talk time} min talk, {Q&A} min Q&A - review {n} of {total}
Promise checked against: {accepted abstract, one line}

Keep
- {moment}: {why it works}

Blocking (only from the Blockers list)
- {moment}: {effect} -> {suggestion or question}

Change (max 3 including blocking)
- {moment}: {effect} -> {suggestion or question}

Optional (take or leave)
- {one line each}

Next milestone: {date, what happens}
```

## Post-run script, one listener

Run within the same session, before the speaker starts self-criticising.

1. "How did that feel?" Listen; do not correct.
2. "Here is what I want you to keep." Two specific keeps.
3. "Is there a part you already know you want to change?" Their list first, often it overlaps yours.
4. Up to three changes, each: observation, impact, request or question.
5. "What will you try before the next run?" The speaker names it, not you.

## Critical Response Process for a group dry run

Facilitator holds the order. About 20 minutes per talk, after the run.

1. **Statements of meaning** - each listener: what was striking, useful, memorable.
2. **Speaker asks** - the speaker asks listeners about what worries them ("Did the demo section drag?").
3. **Neutral questions** - listeners ask without hiding an opinion. "Why did you open with the graph?" is neutral; "Why didn't you open with the story?" is an opinion in disguise; the facilitator rephrases it.
4. **Permissioned opinions** - "I have an opinion about the ending, do you want it?" The speaker may say no.

The three-change cap applies to the written summary, not to the conversation: after step 4 the facilitator writes any Blocking item first (it counts toward the three), the speaker picks the remaining opinions they want written down, and the keeps from step 1 go on top.

## Facilitator brief

For whoever runs a group dry run. Read it aloud at the start so speakers know the rules too.

- One talk at a time, run uninterrupted, timed against the talk time.
- Then the four steps in order. Rephrase any opinion disguised as a question.
- Nobody comments on a speaker's accent, voice or appearance; audibility notes point at a moment and the room.
- What is said in the session stays in it. Recordings only with the speaker's yes.
- Write each speaker's summary within a day: keeps, then at most three changes.

## Speakers presenting in a second language

- Offer, never require, a scripted opening and closing: the moments nerves hit hardest.
- Allow fuller speaker notes; reading them is not a failure.
- Pace and clarity notes are fine when anchored to a moment and the room. Accent notes are not.
- Suggest putting key terms on the slides, which helps the audience and the captioner as much as the speaker.

## When the speaker pushes back

- On a non-blocking note: accept it. The talk is theirs.
- On a blocking note: restate the effect and ask for their fix. Escalate to the program chair only per the Blockers list, and tell the speaker first.
- On the whole process ("I don't want coaching"): thank them, keep their dry-run slot open, stop contacting them about it.
