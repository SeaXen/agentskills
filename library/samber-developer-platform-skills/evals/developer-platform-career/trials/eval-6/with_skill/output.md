# Take Ardent Pay, after four checks

**Target:** Platform Engineer/Architect track at an infra/API-first company. This is a recommendation on the information you gave me, not a verified comparison. The checks below can change it.

## Scope check

All three roles serve **external** developers: Ardent's payments API, Glenview's new public API, and the ISV ecosystem of the enterprise. None is an internal developer platform role (Kubernetes, Backstage, golden paths). So "platform" means the same thing across all three, and the comparison is valid.

|---|---|---|---|
| Archetype | Infra/API-first | Bolt-on public API | Enterprise partner/ISV ecosystem |
| Track | Platform Engineer/Architect | General backend with API ownership | Partner/Integration Engineer |

## Why Ardent

1. **Archetype.** Ardent is the one place where the API is the product and a dedicated team exists to protect it. This is the highest-depth seat in the field.
2. **Level.** Staff against Senior is a real rung gap, even with base within 8%. Platform pay follows the general engineering ladder, so a Staff title carries a higher band at every later step. The 8% base gap hides most of that difference, which sits in equity, bonus and the next promotion.
3. **Compounding.** A payments API with other developers' money flowing through it forces contract-stability and misuse-resistance judgment. That judgment transfers to any later employer. Brandur Leach's point applies: once one user consumes an interface, you lose the freedom to change it.
4. **Peers.** Nine people on a platform org means design review, and people to learn from.

## Why not Glenview, and when it wins

- **"Own the API end to end" in a 6-person backend team is the bolt-on pattern.** Postman found 84% of API teams have 1–9 people. Expect to absorb API design, partner questions and general backend work all at once.
- **Two risks apply.** The first is under-leveling, since Senior may undersize the real scope. The second is being pulled into general backend delivery, which is what you'd be measured on.
- **A first public API has no peer review.** You'd be setting contracts that can't change later, with nobody to challenge them.
- ⚠️ **Glenview wins if** you want greenfield ownership and visible scope more than depth and rung, *and* you get these answered:
  - Who reviews API design decisions?
  - Is there a written compatibility promise?
  - What share of your time is API versus general backend work?
  - Is a Staff-equivalent level available on this scope?

## The enterprise recruiter

- **It's a conversation, not an offer.** Don't let it delay a decision on two real offers.
- **The role differs in kind.** A Partner/Integration Engineer is relationship-facing and measured on partner metrics you can't fully control, like the partner's own adoption pace. That is a different job, not a weaker version of Ardent's.
- **Keep it warm only if it costs nothing.** Ask the recruiter for level, comp band, and whether the team has a named manager and director. If the offers' deadlines expire first, drop it.
- ℹ️ **Consider it later if** you want ecosystem and partner work over deep API design. It fits that goal better than Ardent does.

## Four checks before you sign Ardent

1. **Level scope.** The one sourced Staff bar for this function is Stripe's: 12+ years, 5+ in strategic technical leadership, and leading teams on API design, abstractions, frameworks or client libraries. That is one company's bar, not an industry standard. Confirm Ardent is hiring you to lead that work, not to be a strong Senior with a Staff title.
2. **Compensation.** Base is within 8%, but equity and bonus are unknown to me. Compare each offer against the *general* software-engineering band at that company and level. Search Levels.fyi by "Staff Software Engineer" (Ardent) and "Senior Software Engineer" (Glenview), not by "platform engineer". I have no verified figures, so pull current ones with source and date before negotiating.
3. **Platform org health.** Ask Ardent who owns breaking-change decisions, how API design review works, and how the nine people split across API surface, SDKs and infrastructure.
4. **Your goal.** I assumed durable, compounding platform judgment over the fastest next move. If you need the shortest path to a specific outcome, tell me and I'll re-rank.

## What would change this

- **Ardent's scope is vague or the level is nominal.** Then Glenview's explicit ownership looks better.
- **You want partner and ISV work.** Then the enterprise role moves up.
- **Glenview offers a Staff-equivalent level and comp.** Then the gap narrows and the decision becomes archetype against ownership.
