# Docs structure audit — Larkfield Data Cloud, 2026-09-18

## Verdict

Nineteen findings, one platform constraint (no redirect layer this quarter), and one writer at 6h/week. The queue below fits inside a quarter with room left over. The single highest-leverage move isn't on your list: check whether your nav config is decoupled from your URL paths — if it is, 12 of your 19 findings (the 9 misplaced pages + 3 confusing section names) cost almost nothing and don't need a redirect at all.

## Before you build tickets — one five-minute check

Open your nav config (`mkdocs.yml nav:`, `sidebars.js`, `docs.json navigation`, `SUMMARY.md`, Starlight `sidebar`, whatever you run) and check: **does a page's URL come from its file path, or from the config entry?**

- **Decoupled** (true for most of MkDocs explicit nav, Docusaurus explicit sidebars, Mintlify, GitBook, Astro Starlight): you can re-point where a page *appears* in navigation, and relabel a section, without touching the file or its URL. No redirect needed for either.
- **Coupled** (Docusaurus *autogenerated* sidebars, Hugo sections, Sphinx toctree-by-directory): the URL is the folder path, so moving a page's home changes its URL. That's a real move, and it's exactly what your no-redirect constraint blocks.

This one check decides whether items 2 and 5 below ship this week or get parked for a quarter. Do it before triaging anything else — it also decides where new pages (the Terraform how-to) and split-off reference pages should land, so it gates the sequencing, not just two line items.

## Findings

**[must fix] Connect to Snowflake — duplicate, disagreeing on the required IAM role**
- Now: the procedure lives twice — a standalone guide and onboarding step 3 — and the two now specify different IAM roles.
- Reader impact: whichever copy someone *didn't* read is now wrong for them: too narrow a role fails the connection, too broad over-provisions access. This sits on the mandatory onboarding path, so every new account hits it.
- Next action: get the data-platform/security owner to confirm the correct role once (this audit doesn't adjudicate which role is right — that's an accuracy call, not a structure call). Make the standalone guide the single source of truth. Replace onboarding step 3's full procedure with two lines and a link to it. No URL disappears, so no redirect is needed — you're removing the second copy of the *content*, not the *page*.

**[must fix] no how-to for the Terraform provider**
- Now: nothing in the docs covers the Terraform provider. 18 support tickets in 90 days ask for it — roughly 1.4/week, a standing pattern, not a spike.
- Reader impact: every reader adopting Data Cloud through infrastructure-as-code (a different audience than the console-click path — platform/infra engineers, likely enterprise-leaning) has no supported route and opens a ticket instead.
- Next action: write one **how-to**, not a tutorial. Diátaxis classifies by what the page does, not what people ask for by name: someone reaching for the Terraform provider already knows Terraform, so they need a working provider block through first `apply`, not a lesson in Terraform itself — same "no configuration menus" pattern the tutorial mode forbids. Route it into whichever section holds your other integration/deployment content, once that section's name is fixed (see below) — don't publish it into a section you're about to rename.

**[should fix] 6 pages mixing a procedure with a full option table**
- Now: each page runs numbered steps straight into a full configuration table on the same URL — the textbook "how-to plus reference" mix.
- Reader impact: someone executing the procedure scrolls past a table they don't need yet; someone looking up one setting later re-reads steps they've already done.
- Next action: on each page, lift the table onto its own reference page, leave a link where the table used to sit. The procedure keeps its original URL and content shape — the new URL is *net-new*, so nothing here needs a redirect either.

**[should fix] 9 pages in the wrong section**
- Now: 9 pages sit under a section that doesn't match their content or the job the reader came to do.
- Reader impact: a reader following the nav for one task lands among pages meant for a different one, and either backtracks or bails to search.
- Next action: gated on the check above. Decoupled nav → re-point 9 nav entries to the correct section in one sitting, no file moves. Coupled nav → this is a real move; delete it from this quarter's queue and log it as blocked on the redirect layer for the next platform-team planning cycle.

**[worth noting] 3 section names nobody understands**
- Now: 3 top-level labels don't tell a reader what's inside before they click.
- Reader impact: readers guess wrong from the nav and either backtrack or search instead of browsing — a smaller cost than a missing page, but a recurring one.
- Next action: same gate. Decoupled → rename the label immediately, ships in the same sitting as the nav batch above. Coupled → don't rename this quarter (every child URL would move with the label); instead add a one-line description under the existing label if your generator supports a category description field. That's free either way and buys clarity without touching a single URL.
