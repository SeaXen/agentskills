## Verdict

Launch, but don't run it as a pure Q&A stream.

- Demand is thin: 2 support questions and 1 Discord thread.
- Engineers are "happy to join when they can", so staffing is not committed.
- A Q&A stream with an empty chat gives you an empty room on camera, and the recording is content nobody wants.

**Fix:** Each session is 30 minutes. It opens with a 10-minute prepared demo or walkthrough, then answers questions. The session has value even if nobody asks anything.

## Format (each Thursday)

1. 0:00 to 0:10: Prepared segment. Use the top question of the week, or a task like "send your first event in 5 minutes".
2. 0:10 to 0:30: Questions. Take pre-submitted ones first, then live chat.
3. Fallback if chat is silent: walk through the 3 most common support, Discord and GitHub questions of the week. If those are empty too, read the SDK's rough edges aloud and show the fix. Never say "no questions, see you next week."

## Staffing

- You host every session.
- Put one engineer on a booked rota: Week 1 engineer A, Week 2 engineer B, and so on. Get a calendar hold, not "when they can".
- Ask each engineer for one thing: 30 minutes on their week, plus 15 minutes of prep on the question topics.
- Skip the backup engineer. If the booked one is out, you run it alone and say "I'll take it to the team" for deep questions.
- Time cost for you: about 2.5 hours per week. That is 1 hour of prep, 30 minutes live, 30 minutes of editing and posting, and 30 minutes of follow-up replies.

## Fill the room (this week)

1. Today (30 min): List 20+ beta users by name. Pull them from signups, GitHub issue authors, stargazers who forked, the Discord thread, and the 2 support tickets.

## YouTube setup (45 min, once)

- Use OBS at 1080p with an editor font of 18pt or larger and a dark theme. Turn notifications off.
- Make a demo project with throwaway API keys. Rotate them after each session, because live streams leak secrets.
- Set chat to hold links for review, and add one moderator (an engineer).
- Make a reusable thumbnail template. Use the title pattern "Lanternfold Office Hours #N: [topic]", with the topic first so search finds it.
- Fall back to Discord voice or a quick unlisted stream only if YouTube fails.

## Recordings as content

- Don't publish every raw recording. Publish only sessions with at least one real question answered.
- Add chapters and a timestamped description, with a link to the docs for each answer.
- Cut each good answer into a 30–60 second short or a short clip. Title it with the question text, because that is what developers search.
- Add each answer to the FAQ and docs. That is the evergreen asset.
