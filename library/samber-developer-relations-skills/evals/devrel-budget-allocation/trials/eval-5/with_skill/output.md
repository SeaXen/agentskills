# Caldera Systems — DevRel Budget Benchmarks for the Board

Short version up front: two of the three numbers the board is asking for don't have a real external benchmark behind them — no published source is trustworthy enough to defend under questioning. The third is computable but Caldera hasn't tracked the one input it needs yet. Here's each number handled honestly, plus where Caldera actually sits.

## 1. DevRel spend as % of ARR

**Refused as an industry figure.** The only annual survey in this space — *State of Developer Relations 2024* (DevRel.Agency, 310 respondents/242 completions, published 2024‑09‑10) — never asks about revenue at all. It reports absolute budget bands (e.g. $101K–$500K) and a spend-allocation split across four categories from just 47 people who could even state a number, and those shares sum to 104.5% because respondents mixed salary-in and salary-out answers. There is no revenue denominator anywhere in that dataset, and no other credible devrel-specific source fills the gap. Anyone who hands the board a "devrel should be X% of ARR" figure is quoting a number nobody actually measured.

**Caldera's own number (self-computed, this period):** $260K / $14M ARR = **1.9%**.

This isn't a target to hit or miss — it's day one. Label it a **program baseline**: the number this year's spend produced, which next year's ask gets compared against. The board question worth answering isn't "is 1.9% right," it's "what did the $260K buy, and is more of it worth funding" — that's a line-item threshold conversation, not a percentage-of-revenue one.

## 2. Cost per developer reached

**Also on the refuse list** — explicitly, per the same reasoning: no published source reports this, and any number offered without one would be invented. Unlike the ARR question, this one is legitimately computable — but only once Caldera defines and counts "developers reached" for the period (unique docs visitors, community members, event attendees — whichever the program treats as its acquisition surface). That count wasn't part of what you gave me, so I'm not filling it in with a guess.

Formula once you have it: `program spend ÷ unique developers reached in period`. If salaries are excluded from the $260K (see the flag below), decide that once and hold it — the number is meaningless compared period-to-period if the base keeps shifting.

**What to put on the board slide today instead:** name this as the instrumentation gap it is. "We can't quote this yet because we don't track reach as a single number — fixing that is the first thing next quarter's budget buys" is a stronger board answer than a fabricated ratio, and it's defensible if anyone probes it.

## 3. Headcount-to-budget ratio at Series B

**Refused, and specifically named as unsourceable** — the same survey reports team-size bands (2–5 people is the most common band at 35.2%, solo practitioners 18.2%, 69% of teams under 10) but never crosses team size against budget, and never segments by funding stage at all. "Series B norm" for this ratio doesn't exist in any dataset I can point to. Treat anyone quoting one as guessing.

**Caldera's own number (self-computed):** $260K / 3 people = **~$86.7K of program budget per devrel headcount**.

One flag before this goes on a slide: that math assumes the $260K is *program* spend and doesn't include the three people's salaries. If it does, the ratio means something entirely different (most of it is compensation, not program activity), and the 1.9%-of-ARR figure above shifts too. Confirm which basis you're using — the survey found 60% of programs exclude salaries entirely, so this isn't a pedantic distinction, it's the one thing that changes every number on this slide.

## Board slide narrative (five sentences, no jargon)

We spent $260K on developer relations this year — 1.9% of ARR — across a 3-person team. No credible external benchmark exists for that percentage, for cost per developer reached, or for headcount-to-budget ratio at our stage; the one industry survey in this space is a 47-person sample that doesn't measure any of the three. So we're treating this year's numbers as our own starting line rather than borrowing someone else's. Next year's ask will be judged against what this $260K produced, not against an invented industry average. The one gap we're closing before the next review is tracking "developers reached," so cost-per-developer becomes a real, quotable number instead of a guess.

## What this needs before it's fully load-bearing

- Confirm whether the $260K includes the 3 salaries or not — changes all three numbers above.
- Start counting "developers reached" this period so cost-per-developer exists next time.
- Treat 1.9% of ARR and $86.7K/head as this period's baseline, not a verdict — the useful comparison is Caldera-to-Caldera next cycle, never Caldera-to-survey.
