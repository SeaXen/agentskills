# Quarry v3 LinkedIn Live: run-of-show

**Date:** Thursday 5 Nov 2026. The launch post goes out at 10:00 CET, and the Live starts at 10:10 CET.
**Length:** 20 minutes on air, 3 minutes of buffer.
**Speaker:** VP Engineering. **Producer:** one person, not the speaker.

## Decisions needed before Monday

1. **Check LinkedIn Live access.** It isn't a "go live" button. A company page needs Live access approved, and it streams through a tool (StreamYard, Restream or similar) using a stream key. Check the page today. If access is missing, approval can take days, so the fallback is the VP going live from their personal profile.
2. **Approve the 30% code in writing** (CMO and finance) before Thursday. Don't promise a code live until that's done.
3. **Pick the offer terms.** A public live code leaks to coupon sites within hours. Set these:
   - It applies to Quarry Cloud only. The open-source release stays free.
   - Set an expiry, for example 7 days.
   - Cap it by redemptions (a few hundred) and by first-year or first-invoice discount.
   - Make it a unique-to-this-campaign code, so you can measure and kill it.
4. **Confirm the pricing page is final and public.** Don't show unannounced tiers on screen. The page on screen must match what visitors see after the stream.
5. **Decide on "right after".** Going live the same minute as the post splits attention. Post at 10:00, go live at 10:10, and put the Live link in a pinned comment on the post.

## On-air script (20 min)

| Min | Segment | Content |
|---|---|---|
| 0:00 to 1:00 | **Open** | Who you are, what Quarry is, "v3 shipped 10 minutes ago". Ask people to say where they are watching from. |
| 1:00 to 3:00 | **Why v3** | One sentence on the problem. Name the top 3 changes in plain language. |
| 3:00 to 11:00 | **Demo** | Three features at about 2.5 minutes each. Show before and after for each. Use real queries, not slides. |
| 11:00 to 14:00 | **Open source and cloud** | What stays in the open-source project, what Quarry Cloud adds, and how to try it. |
| 14:00 to 16:00 | **Pricing** | Show the pricing page for no more than 90 seconds. Say who each tier is for. Don't read the table. |
| 16:00 to 17:00 | **Offer** | The producer posts the code and link in the comments while the speaker says it out loud. State the expiry and that it covers Quarry Cloud. |
| 17:00 to 19:30 | **Q&A** | The chat host picks 3 to 4 questions. |
| 19:30 to 20:00 | **Close** | Repeat the one call to action: try v3. Thank the contributors. |

**Demo rules:** keep to 3 features, and don't improvise a fourth. If a demo fails, cut to the recording and move on.

## Comment to post at 16:00

> Quarry v3 launch offer: 30% off Quarry Cloud with code `CODE`, valid until [date], first [N] redemptions. Try it: [link with UTM]. Open-source v3 is free on GitHub: [link]

Use a UTM-tagged link so you can attribute signups to this stream.

## Risks and fallbacks

| Risk | Fallback |
|---|---|
| No Live access approved | Speaker goes live from the personal profile, or run a recorded video post instead. |
| Demo or network fails | Producer switches to the recorded demo. |
| Trolls or spam in chat | Chat host hides and removes comments, no debate on air. |
| The code leaks to coupon sites | Producer disables it in the billing system and posts an update. |
| Hard or hostile question | Speaker says "good question, we'll answer in the post-event thread" and moves on. |
| Pricing question you can't answer | Don't improvise. Point to the page, and follow up later. |

## After the stream

1. **Within 30 min:** the replay stays on the page. Post a short summary comment with the replay link and timestamps.
2. **Same day:** answer every unanswered question in the chat.
3. **Next day:** report views, peak viewers, link clicks, code redemptions, and new signups attributed through the UTM.
4. **Day 7:** the code expires. Close the loop with the CMO on cost against signups.

## Expectation check

Followers aren't guaranteed to get a notification, and a live notification doesn't mean 9,000 viewers. Plan for a few dozen live viewers and use the replay as the main asset. Set the success target in signups, not in live attendance.
