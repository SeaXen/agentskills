No safe number for day-one stars or upvotes. Skill's own measurement ref: PH's oft-quoted "500-1,200 quality-weighted upvotes for Product of the Day" is "repeated everywhere, confirmed nowhere." Same for HN front-page points and GitHub Trending — no published formula, single-anecdote folklore. Inventing a target "produces launch judged against fiction." Don't chase one.

**Do now, before Thursday (10 min):**

1. GitHub repo → Insights → Traffic tab. Record unique visitors, unique cloners, referring sites. Only last 14 days visible — capture now or gone for good.
2. Repo main page: star count, fork count, watcher count.
3. npmjs.com package page (or npm-stat.com): downloads last 7 days, and 7 days before that. New package → second number likely 0. Record as 0, not "no data."
4. Save all 4 somewhere outside GitHub/npm — both panels roll off.

**Why no target, what to watch day 1 instead:**

Baseline near zero (new project) — "hit N stars" meaningless, multiple of zero stays zero. Day 1 measures attention, not adoption:

- Stars-per-hour curve — rising vs flat vs dead by hour 3. Shape, not total, is what Trending/HN sample.
- Unique cloners (Insights → Traffic) — reader moved to tryer.
- Referrer mix — which channel actually sent people vs which felt loud.
- Anchor-thread comment count/rank, wherever posted (HN/PH/Reddit) — engaged vs scrolled past.

Never ask anyone to star or upvote, even teammates. HN and PH penalize solicited/coordinated votes. Penalty invisible — post dies, no explanation given.

**Tracking after day 1, same two tools:**

Day 7 — trial:
- npm downloads vs pre-launch week captured above.
- Cloners still above baseline — interest outlived thread.
- Issues/questions from outside your team — strongest early signal without docs analytics.

Day 30 — adoption, only window separating real use from applause:
- npm download run-rate vs pre-launch week.
- Repeat/returning cloners.
- First external pull request.
- GitHub "Used by" / dependency-graph count — your substitute for "dependents," no analytics tool needed.

**Gap to know:** no docs-page or landing-page analytics. Can't see quickstart drop-off, and GitHub/npm strip much of the referrer data into "direct." Free fix, no new tool: put distinct link-shortener URL on each channel's post before publishing. Gives click counts per channel after the fact.
