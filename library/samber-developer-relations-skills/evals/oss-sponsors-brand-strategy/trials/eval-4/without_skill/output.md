Here's the sequence, decoupling the routine billing switch from the conference-scale commitment so neither blocks the other:

## 1. This week — flip billing to invoiced now, while volume is small

- **Confirm all 23 sponsorships are active** (not paused/lapsed) before requesting the switch — GitHub's invoiced billing snapshots your active sponsorships at switch time to build the first invoice.
- **Submit the switch from card to invoiced billing** in the org's Sponsors billing settings. Note the eligibility threshold and exact terms can change — confirm the current minimum-spend requirement in your org's billing page rather than assuming last year's number still holds.
- **Don't add or resize any sponsorships during this transition.** Keep the first invoice a clean like-for-like match to what the card was already charging ($2,400/mo), so the controller can sign off on "invoice = card charge" without noise from unrelated changes.
- **Treat this as a dry run for the AP workflow**, not just a settings toggle: get GitHub set up as a vendor, assign a PO/cost-center code, and route the first invoice through whatever approval chain the controller wants — at $2,400/mo, mistakes here are cheap to fix.

## 2. Same week, in parallel — open the $150k program as its own approval track

- Don't fold this into the billing-switch request. It's a materially different action (a public, multi-week-out financial commitment), and bundling it risks either slowing down the routine switch or getting the big number rubber-stamped without proper scrutiny.
- Get budget sign-off and legal/comms review started now — a public dollar figure announced from a stage is a commitment your controller and leadership need to have approved before it's said out loud.
- **Decide the funding mechanism before the announcement, not after.** $150k as a short-window program may not map cleanly onto "23 individual GitHub Sponsors relationships" — figure out whether it runs through GitHub Sponsors directly, a fund/vehicle (Open Collective, Thanks.dev, a foundation), or an internal grants process with published criteria for who qualifies and how they apply.
- If it does run through GitHub Sponsors, contact GitHub's Sponsors/account team directly — invoiced billing as self-serve is built for steady recurring sponsorship, not necessarily a lump-sum spike, so confirm it supports the volume and disbursement shape you're planning.

## 3. First invoice cycle — reconcile before touching anything else

- When the first invoiced-billing statement lands, reconcile it line-by-line against the prior card charges. Get explicit controller sign-off that the new process is trustworthy before layering the bigger program on top of it.
- Use this cycle to confirm proration behavior (how the mid-cycle switch was billed) so there's no surprise when the run-rate jumps after the announcement.

## 4. Two to three weeks before the 14th — get payment rails ready, not just the announcement copy

- Finalize whatever mechanism you picked in step 2 so money can actually start moving the moment the program is announced. A gap between "we announced $150k" and sponsorships/grants going live is the visible failure mode to avoid.
- If it's flowing through GitHub Sponsors, get the new run-rate pre-confirmed with GitHub so the next quarterly invoice reflects it correctly rather than triggering a manual correction.

## 5. At/after the announcement — re-baseline and set a recurring cadence

- Re-baseline the quarterly invoice estimate for the new scale.
- Set a standing reconciliation cadence with the controller (monthly or quarterly) now that the number is two orders of magnitude larger — the informal "check it when it looks off" approach that worked at $2,400/mo won't scale to $150k.

**Why this order:** the controller's ask is low-risk and time-boxed ("this week"), so do it while the numbers are small and any process kinks are cheap. The $150k program is high-visibility and hard to reverse once announced, so it needs its own approval and payment-mechanism work running in parallel — starting now, but validated well before the 14th, not compressed into the same week as the billing switch.
