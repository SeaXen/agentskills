### Why each ask gets cut

- **Architecture** — earns its place when a reader is judging whether to build *on top of* something (a framework) or run it as infrastructure (a service). A 200-line parse/re-emit crate has no architecture a reader needs before calling the function. Adding a section for it manufactures complexity that doesn't exist, which reads as trying too hard, not as rigor.
- **Roadmap** — the *only* legitimate thing hiding inside this ask is project status, which genuinely is one of the two most valuable things a README can say (present in just 21.4% of README's sampled in the research this skill is built on, vs. 88.5% for install docs — it's genuinely scarce, not filler). But a roadmap section promises *future* work, which is exactly the ongoing commitment you said you have zero appetite for. Say the status, skip the promise.
- **Governance** — this section exists to reassure a procurement reviewer evaluating supply-chain risk on behalf of a company. You have no such reader. An empty governance heading on a weekend crate reads as cargo-culting a foundation template, which is worse than no heading at all.
- **Security policy** — same category as governance: it's a trust signal for enterprise adopters, and the moment you publish one, you've publicly committed to a response window you now have to honor. That's a legal-shaped obligation dressed as a doc section — the exact thing you ruled out.
- **Demo GIF** — earns its place when the *output* is the product: a CLI, a visual tool, something with a terminal transcript worth watching. `parse(str) -> Ulid` has no interesting visual output — a GIF of a function call and a print statement teaches a reader nothing a one-line code example doesn't. ("Most top repos have GIF demos" is a folklore stat with no real source behind it, in case that's where the advice came from — worth knowing if your friend brings it up again.)

None of this is "your friend is wrong to want the project to look serious" — it's that padding is what makes a small utility look *less* mature, not more. A four-section README on a 200-line crate reads as a maintainer who knows exactly what they built. A four-section README plus an empty Governance heading reads as a template nobody finished.

### The one real gap

Your README doesn't say why to use it over the alternative — and that's the single scarcest, highest-value thing a README can say (present in roughly a quarter of READMEs sampled in the same research). It costs one paragraph, not a section, and it's the one thing on this list that's actually worth your time.

Drop this above the install block:

```markdown
## Why bitrune

[One or two sentences on the concrete difference — a number if you have one: parses in
one pass with no allocation / has zero dependencies / handles the Crockford Base32 edge
cases <alternative crate> gets wrong / is 200 lines instead of a general-purpose ID
toolkit. If you genuinely don't have a differentiator over the obvious alternative, say
that instead — "this exists because I wanted a version with X" is honest and still
useful information.]
```

I've left it as a template rather than writing the actual sentence, because I don't know your ULID landscape well enough to make a claim I can't check against source — and an unverifiable differentiation claim is worse than none. Fill in the bracket yourself; it's the only part of this that requires you to know something I don't.

Pair it with one status line, since that's the other cheap, scarce, genuinely valuable thing — no section needed, one sentence wherever it reads naturally (top, or right after the one-liner):

> Stable and feature-complete for its scope — I maintain it on weekends, so expect a slow response to issues, not no response.

That single sentence does everything "roadmap" was trying to do, honestly, and costs you nothing ongoing.

### Two zero-cost, zero-commitment optional adds

Not asked for, not required — mentioning because they cost one line each and never obligate you to anything:

- **crates.io / docs.rs badges** (version + docs link) — these are auto-generated by a third party and can't lie, unlike a hand-written "PRs welcome" badge. Two, not more.
- **MSRV** (minimum supported Rust version), if `Cargo.toml` declares `rust-version` — Rust readers check this before adding a dependency, and it's one fact pulled straight from a file you already maintain, not a new claim to keep up to date.

Skip both if even one line feels like more upkeep than you want — the differentiation sentence and the status line are the only two that matter.
