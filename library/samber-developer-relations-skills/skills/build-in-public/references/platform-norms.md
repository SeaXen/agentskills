# Platform norms

Build-in-public content does not transfer between platforms. Each has a distinct audience, an accepted format, and a specific way that a badly matched post fails.

## The table

| Platform                       | Audience                          | Accepted format                                                                              | What fails there                                                                                                      |
| ------------------------------ | --------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| X / Twitter                    | Indie hackers, founders, makers   | Revenue-dashboard screenshots, milestone posts, weekly recaps, "day N of building X" threads | Corporate PR tone, no personality, pure promotion; unverified revenue claims now draw skepticism rather than applause |
| Indie Hackers                  | Bootstrappers                     | Milestone write-ups ("how I got X to $Y MRR"), AMAs, forum threads with real numbers         | Thin self-promotion with no lesson attached; VC-scale bragging                                                        |
| LinkedIn                       | Operators, B2B buyers, executives | Founder-led narrative updates: story plus insight, less raw revenue                          | Casual indie tone; naked metric-flexing                                                                               |
| YouTube devlogs                | Developers, game developers       | Long-form devlogs; the game-dev devlog format carried into SaaS                              | Irregular cadence; low production discipline                                                                          |
| Twitch / live coding           | Developer peers                   | Live building, pair-style sessions                                                           | Needs real-time polish; reach is narrow                                                                               |
| Open metrics dashboards        | Prospects, peers                  | A live page of the numbers you committed to                                                  | Live numbers amplify the downside of a bad quarter; an abandoned dashboard signals decline louder than no dashboard   |
| Changelogs and public roadmaps | Users, contributors               | Public boards, repository projects, upvoting, RFCs                                           | Promised dates; a roadmap detailed enough to read as competitor intelligence                                          |
| Newsletters                    | Warm, already-converted audience  | Essays plus numbers, sent on a fixed rhythm                                                  | Inconsistent sending; no fit between the channel and what you sell                                                    |
| Reddit / Hacker News           | Skeptical technical readers       | Post-mortems, "Show HN", candid retrospectives                                               | Marketing language, hype and unverifiable metrics are actively punished                                               |

## Mechanics worth knowing

**The short half-life of a social post.** A peer-reviewed 2023 study (Pfeffer, Matter & Sargsyan, published at ICWSM) measured actual Twitter API impression data and found a median tweet half-life of about 80 minutes, with impressions peaking around 72 seconds after posting and dropping to near-zero for ~95% of tweets within 24 hours. Marketing-industry trackers using engagement proxies (retweets, likes) instead of impression data report a shorter 18-24 minute figure - the two disagree because they measure different things, not because either is wrong. Either way, plan around the shape both describe: no single post carries a funnel. Cadence and repurposing do the work, which is why the anchor surface has to be one you own.

**Open dashboards are a contracting genre.** They are the purest artifact of the open-startup lineage, and several of the pioneers who invented the genre have since withdrawn their own. Buffer and Plausible remain live exemplars worth pointing a user at; a dashboard that stopped updating is a cautionary example, not a template.

**Verifiability now beats polish.** With screenshot-faking tools in circulation and a verified-revenue service built specifically as a countermeasure, an unverifiable revenue screenshot reads as more likely fabricated than impressive. If numbers get published, publish them from a source a reader can check.

## Choosing the mix

1. Name one anchor surface the project owns - changelog, blog, or newsletter. It keeps the archive when a platform decays or an account is lost.
2. Add amplifiers only where this project's audience already evaluates tools, and only channels the maintainer actually reads. Posting into a community you don't read is how norm violations happen.
3. Rewrite per channel rather than cross-posting. A milestone post and a post-mortem are different genres, not one asset reshaped - treating them as interchangeable is the failure mode the table above describes twice.
4. If you can browse the web, check each candidate channel's current self-promotion rules before recommending it. They change, and breaking them costs the account rather than the post.
