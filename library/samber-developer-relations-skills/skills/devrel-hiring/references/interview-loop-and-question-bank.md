# Interview loop and question bank

Contents: the verified format set · loop design per sub-role · the question bank by competency · scoring mechanics.

## The verified format set

There is no standard DevRel loop - candidates report meeting any subset of these for the same job title. Pick 3-5 formats that actually test the target sub-role's pillar mix; running every format regardless of role wastes interviewer hours on tests that do not discriminate for this seat.

| Format                              | What it tests                                                                           | Best for                              |
| ----------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------- |
| Presentation round                  | the core public artefact of the job: clarity, pacing, audience read, handling questions | outreach advocate, community manager  |
| Content take-home (a post or video) | writing a developer would trust: shows the code, admits trade-offs, no marketing voice  | outreach advocate, developer educator |
| Coding take-home                    | can build what they will advocate                                                       | product-focused advocate, DX engineer |
| Technical self-rating questionnaire | breadth calibration and honesty - inflated self-ratings unravel in the next round       | any role, as an early screen          |
| Conversational rounds               | technology fluency, community experience, collaboration style                           | every role                            |
| DevRel-opinion round                | the candidate's model of the practice itself - has no memorised right answer            | senior hires, any role                |
| Founder / exec round                | commercial understanding and culture fit                                                | early-stage startup hires             |

Place the portfolio evaluation (Artefact 3 in the skill body) before any new work is requested - judging existing public work first often removes the need for a content or coding take-home entirely.

## Loop design per sub-role

| Sub-role                  | Suggested formats                                                                                     | Stage count |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | ----------- |
| Outreach-focused advocate | portfolio evaluation, presentation round, conversational round, DevRel-opinion                        | 3-4         |
| Product-focused advocate  | portfolio evaluation, coding take-home, conversational round, DevRel-opinion                          | 3-4         |
| Community manager         | portfolio evaluation, conversational rounds (conflict-handling emphasis), presentation round optional | 2-3         |
| Developer educator        | portfolio evaluation, content take-home, conversational round                                         | 2-3         |
| DX engineer               | portfolio evaluation, coding take-home, technical conversational round                                | 2-3         |

Add a founder/exec round for any early-startup hire regardless of sub-role.

## Question bank by competency

Write 2-3 questions per scorecard competency; include at least one DevRel-opinion question per loop.

**DevRel philosophy and strategy**

- What is developer relations for, at a company like ours? (Tests whether they can name a funding driver and pillar mix, not recite a definition.)
- How would you measure your own work here, and what would you refuse to be measured on?
- How do you align DevRel initiatives with the product roadmap?

**Content and communication**

- Walk me through a piece of content you shipped and what it changed.
- How do you keep a tutorial correct after the product changes underneath it?
- How do you translate a complex technical concept for a non-expert audience without losing accuracy?

**Community management**

- How do you identify and grow community leaders or ambassadors?
- Describe a toxic or hostile thread you handled, and the outcome.
- What community-health metrics do you actually trust, and which do you distrust?

**Technical depth**

- How do you evaluate whether documentation is accurate and current?
- Describe your experience integrating with an SDK or API you didn't build.
- How deeply do you expect to understand our architecture, and how would you get there?

**Public speaking**

- How do you prepare a technical talk for an audience with mixed backgrounds?
- How do you handle a live demo failure or a hostile question mid-talk?

**Metrics and measurement**

- What DevRel metrics have you owned, and which did leadership actually believe?
- Tell me about a time data changed a DevRel decision you'd already made up your mind about.

**Behavioural and scenario-based**

- Tell me about developer feedback you carried into a product decision that shipped - name the change.
- A major product delay threatens community momentum. What do you do in the first week?
- A key community contributor leaves. How do you manage the transition?

**Cultural fit**

- How do you stay current with the ecosystem you're advocating in?
- Describe how you've mentored someone junior into a public-facing role.

## Scoring mechanics

- Every interviewer scores independently, with a written evidence note per competency, before any debrief happens.
- Combine scores mechanically against the scorecard's pre-set competency weights. This is a general employment-selection finding - structured, independently-scored, mechanically-combined interviews outperform unstructured ones and holistic group debriefs - not a DevRel-specific one, but nothing about the finding is domain-specific, so it transfers directly.
- The debrief calibrates interpretation of already-submitted scores; it never originates a score.
- Never let a technical self-rating questionnaire gate or veto a candidate on its own - use it to target follow-up questions in the conversational round.
