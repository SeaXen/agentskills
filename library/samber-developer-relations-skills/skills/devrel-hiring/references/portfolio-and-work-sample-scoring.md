# Portfolio and work-sample scoring

Contents: applying the six-signal rubric from the evaluator's side · negative signals to name · designing a paid work sample when the portfolio is thin.

## The six-signal rubric, applied

The full rubric, its scoring bands, and the candidate-facing framing live in `samber/developer-relations-skills@devrel-career`. This file is the same instrument read from the hiring side.

Score each 0-3: 0 absent, 1 claimed but unevidenced, 2 evidenced, 3 evidenced with a stated outcome.

| #   | Signal                   | What a 3 looks like                                                                                             |
| --- | ------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 1   | Public writing           | Published posts with a link, on a niche this role cares about, at least one showing a result                    |
| 2   | Public speaking          | Two or more talks with links to video or slides; a lightning talk counts                                        |
| 3   | Code in public           | Repos a stranger can run, matching the target product's surface, with a contribution history                    |
| 4   | Community evidence       | A role held (moderating, organising, mentoring), not membership                                                 |
| 5   | Teaching artefact        | A tutorial, workshop, or learner journey with checkpoints                                                       |
| 6   | Developer-voice artefact | A published friction log, feedback synthesis, or issue thread showing user research reaching a product decision |

Weight by the target sub-role: outreach advocate on signals 1+2; product-focused advocate on 3+6; community manager on 4; educator on 5; DX engineer on 3+1.

Score bands, as this skill's own working baseline (not a published industry standard - move them for a stated reason): under 6 total, the candidate needs more shipped work before this loop can evaluate them fairly; 6-11, evaluate the weighted signals for this specific sub-role; 12+, the constraint is targeting fit, not evidence volume.

## Negative signals to name explicitly

Name these when present, rather than only listing what to add - a hiring manager who only lists gaps lets a real red flag pass silently.

- Follower count with no substance behind it.
- Content that only talks about the candidate rather than the developers they served.
- No shipped code and no public artefacts at all for a product-focused or DX role.
- Ghostwritten or paywalled content that the candidate cannot defend in conversation.
- Metrics exaggerated, or dismissed entirely when asked.
- Cannot name a specific developer or team they helped.

## Designing a paid work sample when the portfolio is thin

Never request unpaid spec work when a public portfolio already exists - offer a paid live working session instead. When the candidate is new to the field and has little public work to evaluate, design a short, scored, paid exercise matched to the target sub-role:

| Sub-role                 | Work-sample design                                                                   | Scored on                                                  |
| ------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Outreach advocate        | A 5-minute lightning talk on a topic the candidate picks within the product's domain | Clarity, audience read, handling one injected question     |
| Product-focused advocate | Review a real (anonymised) support thread and propose the SDK or docs fix            | Root-cause read, fix quality, communication to engineering |
| Community manager        | Draft a response to a real (anonymised) hostile community thread                     | Tone, de-escalation, policy consistency                    |
| Developer educator       | Edit a rough internal tutorial draft for a specific learner persona                  | Pedagogical structure, accuracy, accessibility             |
| DX engineer              | A short, scoped integration or SDK-usage exercise against the actual product         | Working code, README a stranger could follow               |

Freeze the rubric for a quarter once set, so every candidate for the role is scored against the same bar.
