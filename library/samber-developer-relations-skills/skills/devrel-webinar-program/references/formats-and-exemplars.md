## 1. Episode skeletons

Times assume a 40-minute slot. Open every episode with the problem, the payoff and what happens to the recording; never open with housekeeping. Turn live captions on for every format.

**Engineer conversation**

1. 0-3 min - the problem the system had, in production terms.
2. 3-25 min - host asks; engineer answers with diagrams, code or dashboards. Five prepared questions, sent to the engineer a week ahead.
3. 25-35 min - audience questions, pre-submitted first.
4. 35-40 min - one next step: docs page, repository, lab.

**Live demo**

1. 0-3 min - the developer problem and who has it.
2. 3-25 min - one realistic scenario solved end to end; every capability shown answers a step of the problem.
3. 25-35 min - questions.
4. 35-40 min - the next step, matching the series' job.

Run the demo through the live-demo sibling's reliability checks: checkpoints, reset, recorded fallback.

**Q&A episode**

1. Collect questions for a week before; vote or rank them.
2. 0-2 min - scope: what the episode answers, where account, billing and security questions go.
3. 2-36 min - top questions first, each answer under four minutes, link posted in chat.
4. 36-40 min - unanswered questions get a written follow-up date.
5. Optional: an unrecorded after-show for questions people would not ask on a recording.

**Follow-along lab**

1. Send setup steps with the final reminder: account on the free tier, tool versions, a test command.
2. 0-5 min - check everyone is set up; a second staff member handles failures in chat.
3. 5-35 min - build in checkpoints; each checkpoint has a copy-paste catch-up so a stuck attendee rejoins.
4. 35-45 min - what attendees built, how to extend it, questions.

Book 45-60 minutes for labs; the setup check costs real time.

**Customer story**

1. 0-5 min - who they are, the situation before.
2. 5-25 min - what they built or migrated, the decision points, what broke.
3. 25-35 min - questions, moderated by the host.
4. 35-40 min - what the customer would do differently.

Get the customer's approval for the title, the slides and the recording before promotion starts.

**Panel**

1. Three panelists maximum, one moderator who has read each panelist's recent work.
2. One question the panel disagrees on, announced in the title.
3. 0-5 min framing; 5-30 min four prepared questions; 30-40 min audience questions; final minute each panelist's one takeaway.

## 3. Patterns across the exemplars

- Four archetypes recur: engineer-to-engineer "how we built it", follow-along labs on a free tier, community Q&A, and community-sourced talk marathons.
- Customer stories appear mostly at event-tied broadcasts, rarely as the weekly core.
- Speakers come from internal engineers and advocates everywhere, plus top community contributors, open calls for talks, external practitioners and paid partner segments.
- None of the developer exemplars runs a sales demo as its core format.
- Replays are public by default; gating, where it exists, sits on labs, badges and credentials.
