## Self-set baselines

These are self-set defaults, chosen to be defensible and easy to move - not published standards. Say so when you use them.

| Baseline                                                                                                                      | Why this value                                                                                                                                                                                            | When to move it                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Contributor absence factor of at least 2, and at least two holders of every privileged credential                             | The smallest value at which no single departure stops releases; derived from the CHAOSS metric plus the foundation "survives one withdrawal" test, applied to a project that has no formal governance yet | Raise to 3+ once the project has paying adopters or is a dependency of other projects          |
| 100% rule coverage - every hard decision of the last 12 months maps to a written rule                                         | A completeness test, not a benchmark; it makes gaps visible without demanding a large document                                                                                                            | Never lower it; lower the number of decision classes instead                                   |
| Evidence the rules ran at least once within two quarters                                                                      | Puts a concrete interval behind the CNCF "demonstrably used" expectation                                                                                                                                  | Shorten for a project applying to a foundation on a schedule                                   |
| Zero contradictions between documented roles and repository permissions                                                       | Binary by nature                                                                                                                                                                                          | Not adjustable                                                                                 |
| Every decision class carries a stated clock                                                                                   | Prevents the unbounded-thread failure                                                                                                                                                                     | Not adjustable                                                                                 |
| Six months of sustained participation, ten non-trivial merged changes, twenty substantive reviews for a maintainer nomination | An illustrative, self-assessable shape; real projects vary widely                                                                                                                                         | Match to the project's actual traffic - on a low-volume project these numbers exclude everyone |
| Key-holder rights granted only after one supervised release cycle                                                             | The minimum separation that would have slowed the xz-utils takeover; the incident analysis recommends staging privileged access                                                                           | Lengthen for artefacts that run with elevated privilege                                        |

## Contested and unresolved

- **Liberal commit access versus staged keys.** Both positions are sourced and genuinely conflict; present both rather than picking one, resolved as step 7 resolves them.
- **Foundation archival rates.** The commonly repeated figure that roughly 15-20% of sandbox projects are archived within three years is unverified against any foundation's own data. Do not quote it as a planning input.

## Known staleness

Governance documents change. Before quoting a named project's threshold, open that project's governance file and confirm the number still reads as stated here - the structural lessons age far better than the integers.
