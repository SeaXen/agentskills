# Staging + bundle pipeline (concrete recipe)

This is the canonical sequence observed working on 2026-08-15 to push `/root/.hermes/skills/` (235 MB, 4,091 files) to `SeaXen/skills-backup` (private). Adjust path / user / repo-name for your own run.

## 1. Survey

```bash
echo "=== full ==="; du -sh /root/.hermes/skills; find /root/.hermes/skills -type f | wc -l
echo "=== big files ==="; find /root/.hermes/skills -type f -size +50M -not -path '*/.git/*'
echo "=== creds ==="; find /root/.hermes/skills \( -name '.env*' -o -name '*.pem' -o -name '*.key' -o -name 'credentials*' \) -not -path '*/node_modules/*'
echo "=== auth ==="; gh auth status
```

## 2. Stage with rsync

```bash
STAGE=/tmp/hermes-skills-backup-$(date +%Y%m%d)
rm -rf "$STAGE"
mkdir -p "$STAGE"

rsync -a \
  --exclude='.hub' \
  --exclude='.curator_backups' \
  --exclude='*.log' \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  --exclude='.DS_Store' \
  /root/.hermes/skills/ "$STAGE/"

du -sh "$STAGE"
find "$STAGE" -type f | wc -l
```

Expected stripped size on SeaXen's box: ~79 MB, ~4,096 files. If you see >120 MB, you probably missed an exclude — re-check `.hub/`, `.curator_backups/`, `*.log`.

## 4. Git init + commit

```bash
cd "$STAGE"
git init -b main
git -c user.email=<user-email> -c user.name=<user-name> commit --allow-empty -m "init"
git add .
git commit --amend --no-edit

# Verify clean top-level
git ls-tree HEAD --name-only | head
```

## 5. Bundle (always do this before push)

```bash
git bundle create /tmp/skills-backup-$(date +%Y%m%d).bundle --all
git bundle verify /tmp/skills-backup-$(date +%Y%m%d).bundle
ls -lh /tmp/skills-backup-*.bundle
```

The bundle is your offline-restore fallback. **Do not delete it** until the user confirms the remote push worked.

## 6. Create GitHub repo

```bash
gh repo create <user>/<repo-name> \
  --private \
  --license MIT \
  --description "Private backup of <user>'s complete Hermes skills library. Mirror of ~/.hermes/skills/."
```

## 7. Push

```bash
cd "$STAGE"
git remote add origin https://github.com/<user>/<repo-name>.git

# Configure for slow upload / GitHub brownout tolerance
git config http.postBuffer 524288000
git config http.version HTTP/1.1
git config --global http.lowSpeedLimit 0
git config --global http.lowSpeedTime 999999

# Run in background — push of 79 MB can take several minutes
git push --progress -u origin main 2>&1 | tail -10
```

## 8. Verify remote

```bash
gh repo view <user>/<repo-name> --json name,visibility,diskUsage,defaultBranchRef
gh api repos/<user>/<repo-name>/contents/ | python3 -c "
import json, sys
files = json.load(sys.stdin)
print(f'root has {len(files)} entries')
for f in files:
    if not f.get('size'):
        print(f'  dir/  {f[\"name\"]}')
    else:
        print(f'  file {f[\"name\"]} ({f[\"size\"]} bytes)')
"
```

## 9. (Optional) Upload bundle as release asset

```bash
cd "$STAGE"
gh release create vYYYY-MM-DD \
  --repo <user>/<repo-name> \
  --title "Skills Backup YYYY-MM-DD (N repos)" \
  --notes "<summary>" \
  --target main \
  /tmp/skills-backup-YYYYMMDD.bundle#skills-backup-YYYYMMDD.bundle
```

Use `--target main`, NOT a commit SHA — `--target <sha>` returns `HTTP 422: target_commitish is invalid`.
