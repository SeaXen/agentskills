# OpenRouter Model Catalog & Picker Architecture

## File Map

| File | Role |
|------|------|
| `~/.hermes/config.yaml` → `model_catalog.providers.openrouter.url` | Override URL for the OpenRouter catalog. Currently points to `file:///root/.hermes/cache/free_openrouter_catalog.json` |
| `~/.hermes/cache/free_openrouter_catalog.json` | The curated list of models offered in pickers. Can contain FREE and/or CHEAP entries |
| `~/.hermes/cache/model_catalog.json` | Disk cache of the last-fetched remote catalog (HTTP cache, auto-managed) |
| `~/.hermes/scripts/openrouter_free_watch.py` | Hourly cron job that rebuilds `free_openrouter_catalog.json` from the live OpenRouter `/api/v1/models` endpoint |

## How the Picker Works

1. `hermes_cli.models.fetch_openrouter_models()` is called by the dashboard/CLI picker AND the Discord/Telegram interactive picker
2. It calls `get_curated_openrouter_models()` which reads the catalog from `model_catalog.providers.openrouter.url`
3. It cross-references the catalog IDs against live OpenRouter `/api/v1/models` to verify they exist and support tool-calling
4. It marks each as "free" or "" based on live pricing data
5. Returns the intersection — models that are both in the catalog AND live AND tool-capable

**Key implication:** If the catalog file contains paid/cheap model IDs, they WILL appear in the picker. The live API filter only checks tool-support, not price. Both Discord/Telegram and the dashboard/CLI picker use the same `fetch_openrouter_models()` function — they should always show the same list.

## Cron Job Behavior (`openrouter_free_watch.py`)

- Runs hourly
- Fetches live OpenRouter `/api/v1/models`
- Identifies free models (prompt=0 AND completion=0 pricing)
- Builds new catalog entries for free models
- **Preserves existing CHEAP entries** from the previous catalog (line ~195: `free_models + cheap_models`)
- Writes to `~/.hermes/cache/free_openrouter_catalog.json`
- Updates auto-aliases in `~/.hermes/config.yaml`
- Sends Discord/Telegram alerts for new/removed free models

**Critical:** Manual edits to `free_openrouter_catalog.json` are overwritten on the next cron run. To make permanent changes, patch the script itself.

**CHEAP model preservation bug:** The `update_catalog()` function separates existing entries into `existing_free_ids` (description starts with "FREE") and `cheap_models` (everything else). It then writes `free_models + cheap_models` back. This means cheap/paid models accumulate across cron runs and are never cleaned up. If you want the catalog to be free-only, you must:
1. Remove cheap entries from the JSON file
2. Patch line ~195 of `openrouter_free_watch.py` to write only `free_models` (not `free_models + cheap_models`)
3. Also remove the `cheap_models` accumulation logic (lines ~155, ~167-168)

## Fixing Paid Models in Picker

1. Check `free_openrouter_catalog.json` for entries whose description doesn't start with "FREE"
2. Decide: does the user want cheap models kept or removed? **Don't assume — ask.**
3. If removing: patch the cron script too, or they'll come back on next run
4. Clear the disk cache: `rm ~/.hermes/cache/model_catalog.json`
5. Reset in-process cache: `from hermes_cli.model_catalog import reset_cache; reset_cache()`
6. Verify: `python3 -c "from hermes_cli.models import fetch_openrouter_models(); print([(m,d) for m,d in fetch_openrouter_models()])"`

## Config Aliases

The `model_aliases` section in `~/.hermes/config.yaml` has an auto-managed block between:
```
  # BEGIN AUTO OPENROUTER FREE ALIASES
  ...
  # END AUTO OPENROUTER FREE ALIASES
```
This block is regenerated by the cron job. Don't manually edit it.

### Pitfall: alias block after `session_reset` breaks YAML

If `openrouter_free_watch.py` inserts the managed block before `# ── Fallback Model` while that header sits **after** `session_reset`, 2-space-indented alias lines become **children of `session_reset`**, not `model_aliases`. Later ticks can leave orphan `  or-auto-...:` lines → CLI error `did not find expected key` (~line 1240+) and Hermes ignores all config overrides.

**Script fix:** insert before `\nplatform_toolsets:` when present; parse `model_aliases` only up to `platform_toolsets`. **Repair:** strip `^fake_key_\d+:` junk if present; move aliases into `model_aliases`; validate with `yaml.safe_load` + `hermes config check`. Agent `patch` on `config.yaml` is blocked — use host Python or `hermes config set`.

Details: `hermes-git-config-snapshots` → `references/openrouter-free-watch-config-corruption.md`.

```bash
cd /usr/local/lib/hermes-agent && source .venv/bin/activate && python3 -c "
import os; os.environ['HERMES_HOME'] = os.path.expanduser('~/.hermes')
from hermes_cli.model_catalog import reset_cache

from hermes_cli.models import fetch_openrouter_models
result = fetch_openrouter_models()
```
