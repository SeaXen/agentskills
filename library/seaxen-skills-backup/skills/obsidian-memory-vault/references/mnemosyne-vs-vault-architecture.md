# Two-layer memory architecture: Mnemosyne vs Obsidian vault

Crisp statement of what each memory layer is and is not, so future
sessions can answer the user's "what is my true memory" type questions
without over-explaining. Built 2026-06-17 after the user asked exactly
this question and the answer landed cleanly.

## The two layers in one table

| Layer | What it is | Editable by user? | Where it lives | Size on this host |
|---|---|---|---|---|
| **Obsidian vault** | **User's true memory** | ✅ Yes — Capture form, manual edits, agent appends | `/mnt/tb/hermes/obsedianvault` | 63 notes, 236 wikilinks, 9 MOC canonicals |
| **Mnemosyne** | Agent's working substrate (auto-captured) | ❌ No — agent writes here, user doesn't see it | `/root/.hermes/mnemosyne/data/mnemosyne.db` | 2,177 working memories, 1,274 facts, 352 triples |
| **Mnemosyne mirror** (in vault) | Read-only snapshot of Mnemosyne | ❌ Auto-generated by `mnemosyne_to_vault.py` cron | `Knowledge/Mnemosyne Mirror.md`, `Knowledge/Mnemosyne Triples.md` | < 200 KB |

## Why the vault is the truth

- **You write to it.** Capture form, manual Obsidian edits, daily notes, `Memory/decisions.md` entries.
- **You read from it.** Recall tab, Reader panel, Graph page, search.
- **Wikilinks are YOUR connections**, not auto-extracted triples. The 236 wikilinks reflect how you think about the world, not what the agent inferred.
- **9 MOC canonicals organize YOUR knowledge** — `decisions`, `issues-fixes-log`, `AGENT`, `Hermes Operations`, `Memory`, `Backup & Disaster Recovery`, etc. Each is curated by you, not by the agent.
- **Mnemosyne flows one-way INTO the vault** (via `mnemosyne_to_vault.py` mirror every 6h). The vault never writes back to Mnemosyne.
- **The dashboard's recall engine reads from the vault**, not Mnemosyne. `/api/recall` and `/api/recall-unified` return vault notes primarily, with Mnemosyne as a secondary unified-recall layer.
- **Daily git sync to private GitHub is the offsite backup.** Mnemosyne has its own backup (`daily-mnemosyne-backup` cron), but the vault is the one in git.

## Why Mnemosyne is NOT the truth

- It's auto-captured from chat sessions, code execution, and agent memory writes. The user never sees most of it.
- 97% of `working_memory` is conversation rows the user wouldn't recognize.
- It is the **substrate the agent uses to think between sessions** — fast FTS5 access to facts it might need — but the durable, human-readable knowledge is the vault.

## When the user asks "what is my true memory"

Give the crisp 3-line answer:
1. The Obsidian vault is your true memory. You write it, you read it, it's in git.
2. Mnemosyne is the agent's working substrate. You don't see it, you don't edit it.
3. Mnemosyne mirrors into the vault as read-only notes, so the agent can recall both layers but the canonical truth is the vault.
